# Contract: projects, the engine/IPC surface, and the board format (redesign steps 2 and 3)

This is the contract the implementation agents build against for steps 2 and 3 of
[the studio redesign](../studio-redesign.md) (§11): **commands take a project** (R-2), the workspace
and its files (R-3, R-4, R-8, R-9, R-10), and **the new board format** (R-5, R-6, R-7). It is written
so that a Rust agent (`unfold-engine` settings, `unfold-store`, `unfold-reader`, `unfold-workspace`,
`unfold-node`) and a TypeScript agent (`desktop/`) can work in parallel without talking. Where this
document and older reference docs (`docs/ipc.md`, architecture §8, §11, §12, `docs/reader.md`)
disagree, this document wins; those docs are rewritten from it as the steps land.

Every R-decision of §9 is accepted. Choices this document makes where the redesign doc is silent are
listed in [§10](#10-decisions-made-here) and marked **(D-n)** where they are used.

**Ground rules (owner, non-negotiable).** Nothing has shipped: no migration, no reader for an old
shape, no shim, alias, adapter, feature flag, or old id. The board format has one shape. The graph
store is a cache. The engine reads files only, never runs code or Git, installs nothing, and writes
only in `.unfold/` and app data. Compilers, linking, resolution, detectors, and graph semantics do not
change. Security (context isolation, sandbox, CSP, `app://`, fuses, trusted commands) does not change;
path confinement is per project. Types are generated from Rust (`cargo xtask gen-ipc`). Rust computes,
TypeScript lays out; queries filter and page in Rust; cross-project search is one fan-out in Rust;
invalidation follows project-scoped events; resting projects hold no watcher.

## 1. Model and identity

| Thing | Identity | Lives in | Notes |
| --- | --- | --- | --- |
| **Workspace** | One per app-data folder (one per machine and user) | `workspace.json` | Every window shows the whole workspace |
| **Project** | `ProjectId`: `"p-"` + 10 chars of `[a-z2-7]`, random, assigned by `add_project` | `workspace.json` row; the folder's `.unfold/` | Stable for the life of the row; survives restarts and worktree switches (D-1) |
| **Project shared name** | `ProjectName`: `/^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/` | `[project] name` in `.unfold/config.toml`, else a default | Names other projects in board files. Cached in `workspace.json` |
| **Worktree** | Absolute canonical folder path | Git's files | One project row per repository; the row points at one worktree folder at a time |
| **Board** | `BoardId` within a project | `.unfold/boards/` or `.unfold/local/drafts/` | Addressed as `{project, id}` |
| **Page** | `PageId` within a board | Inside the board file | Generated by the UI |
| **Card, group, link** | ids within a page | Inside the page | Generated by the UI, as in V1 |
| **Folder** | `/`-separated path within a project | A board's `folder` field; empty folders in `state.json` | Not the disk layout |

### 1.1 Projects and the engine's per-folder workspace

A project row maps to at most one open `unfold_workspace::Workspace` (V1's per-folder object: engine
thread, watcher, store writer, reader cache), keyed by **`ProjectId`**, opened on the project's
current folder. `Workspace` no longer knows windows. Its events carry `project: ProjectId` instead of
`folder: string`. Confinement is the V1 `confine(root, path)` against the project's current folder.

**Shared name.** `[project] name` in `config.toml` (R-3). When absent, the default is (D-2):

1. for a folder inside a Git repository whose common dir is named `.git`: the basename of the
   repository's **main worktree** folder when the project is the repository root, else the basename
   of the project folder;
2. otherwise the basename of the folder;

and if that basename does not match the `ProjectName` pattern, its board slug (`files::slug`). So all
worktrees of one repository share a default name. Resolving a name to a project (for cross-project
cards) picks the **first** connected project in workspace order with that name, the board's own
project included (D-3).

### 1.2 Worktrees (R-4)

Rust reads Git's files, never runs Git (`crates/unfold-workspace/src/git.rs`, new). Each file read is
capped at 4 KiB; a read error means "no repository" for that step, never a failure of the command.

```text
find:     walk up from the project folder P to the filesystem root; the first R with R/.git wins.
          subpath = P relative to R ("" when P == R)
gitdir:   R/.git is a directory  -> gitdir = R/.git
          R/.git is a file "gitdir: <p>" -> gitdir = <p> (relative to R when not absolute)
commondir: gitdir/commondir exists -> resolve its first line relative to gitdir; else commondir = gitdir
HEAD:     gitdir/HEAD: "ref: refs/heads/<name>" -> branch <name>; "ref: <other>" -> branch <other>;
          40 or 64 hex digits -> detached (first 7 shown)
worktrees: main  = parent(commondir) when basename(commondir) == ".git"   (HEAD: commondir/HEAD)
           linked = for each dir W in commondir/worktrees/: first line of W/gitdir is "<root>/.git";
                    root = parent of that path; HEAD: W/HEAD; skipped when W/gitdir is unreadable
           each worktree's candidate project folder = root/subpath; available = is a directory
order:    main first, then by path
identity: repository = (canonical commondir, subpath)
```

- **One row per repository.** `add_project` of a folder whose repository identity matches an
  existing row returns that row (`status: "exists"`); the UI selects it and may offer the switcher.
- **Switching** (`switch_worktree`) re-points the row at another worktree's folder. It is refused with
  `boards_open` while any window holds a board of the project (the calling UI closes its own tabs of
  the project first, saving them). Otherwise Rust closes the live `Workspace` (releasing its lock),
  drops the project's command-side state, writes the new path and the new folder's shared name to
  `workspace.json`, reopens the `Workspace` on the new folder if the project still has interest
  ([§3.3](#33-live-and-resting-projects)), and emits `project_reset`, `workspace_changed`, and
  `project_state`. The graph, published boards, drafts, and `state.json` are the new folder's.
- **Branch changes inside a worktree** (checkout) are seen whenever `workspace` or `git_info` runs:
  HEAD is read on every call (no watching of `.git`). The UI refetches `workspace` on window focus
  and on `graph_updated` with `everything` (D-4).

### 1.3 Board ids (R-5, R-6)

`BoardId` is the folder-relative path of the board's **public** file, exactly as V1:

| Board | `BoardId` |
| --- | --- |
| Draft | `.unfold/local/drafts/<name>.json` (same id when `local/` is in the fallback location) |
| Published, with or without unpublished changes | `.unfold/boards/<name>.json` |

- A published board **keeps its id** when it gains unpublished changes (D-5). The local copy holding
  them is never an id the UI sees.
- The id **changes** on first Publish (draft → published) and on Move back to drafts. The command
  returns the new id; Rust moves the claim, the view state, and recent-board entries itself.
- Draft names: `board-<ms>` (as V1), `-2`, `-3`, … when taken; never ending in `.changes` (D-6).
- A published board's file name is chosen at its first Publish (slug of the title, editable on
  `name_taken`) and never changes afterwards; Rename changes the title only (D-7).

### 1.4 Pages, cards, folders

- `PageId`, card, group, and link ids match `/^[A-Za-z0-9][A-Za-z0-9_.-]{0,99}$/` (the UI's slug-based
  `uniqueId` produces such ids; it must cap them at 100 characters). Page ids are unique in the board;
  card, group, and link ids are unique together within their page. The UI generates them; `new_board`
  names its first page `page-1`.
- A **folder path** is 1–8 segments joined by `/`; each segment is 1–64 characters, has no leading or
  trailing whitespace, no control characters, no `/` or `\`, and is not `.` or `..`. Folder names are
  compared exactly (case-sensitive). A board with no `folder` sits at the project's top level.

## 2. Files

All JSON files Rust owns are written atomically (synced temporary file renamed over the target, V1's
`write_atomically`), pretty-printed with a final newline, and read leniently: a missing or invalid
file reads as the defaults (remembered state never blocks the app). Writes to one file are serialized
by a lock in Rust. Nothing but Rust writes them; the UI uses no browser storage.

### 2.1 `workspace.json` (app data) — new

Written by Rust on: `add_project`, `remove_project`, `reorder_projects`, `set_project_expanded`,
`select_project`, `switch_worktree`, `open_board` (recents), board id changes and deletes (recents),
a shared-name change, a project going to rest, and `shutdown` (last known states).

```jsonc
{
  "version": 1,
  "projects": [                                   // order = sidebar order
    {
      "id": "p-7k2m9q4xab",
      "path": "/Users/l/code/storefront-api",     // canonical path of the current worktree folder
      "name": "storefront-api",                   // cached shared name (refreshed on wake, config_changed, switch)
      "expanded": true,                           // sidebar row expanded
      "repository": { "commonDir": "/Users/l/code/storefront-api/.git", "subpath": "" },  // or null
      "addedAtMs": 1760000000000,
      "lastKnown": {                              // or null (never live yet)
        "state": { "kind": "problems", "count": 2 },   // a ProjectState, never resting/compiling/updating
        "atMs": 1760000500000
      }
    }
  ],
  "selected": "p-7k2m9q4xab",                     // last project selected in any window: the default for new windows
  "recentBoards": [                               // most recent first, at most 20
    { "project": "p-7k2m9q4xab", "board": ".unfold/boards/order-lifecycle.json",
      "title": "Order lifecycle", "openedAtMs": 1760000400000 }
  ]
}
```

At most 64 projects (`too_many_projects`).

### 2.2 `windows.json` (app data) — new

Replaces the per-folder window list of `state.json` and the welcome window's bounds in `recent.json`.
Holds the windows that come back on launch (V1's rule: a window the person closes is forgotten unless
it was the last one; every window open when the app quits comes back).

```jsonc
{
  "version": 1,
  "windows": [
    {
      "key": "6f1c…",                             // stable key the main process assigns
      "bounds": { "x": 80, "y": 60, "width": 1440, "height": 900 },   // or null
      "maximized": false,
      "selectedProject": "p-7k2m9q4xab",          // or null
      "tabs": [                                   // board tabs in order; Home is implicit and always first
        { "project": "p-7k2m9q4xab", "board": ".unfold/boards/order-lifecycle.json", "page": "page-1" }
      ],
      "activeTab": 0,                             // index into tabs; null = Home
      "layout": { }                               // UI-owned JSON (sidebar width and mode, peek pin, lens…)
    }
  ]
}
```

| Writer | Command | Writes |
| --- | --- | --- |
| UI | `save_window_state` | `selectedProject`, `tabs`, `activeTab`, `layout` (keeps bounds) |
| Main (trusted) | `save_window_bounds` | `bounds`, `maximized` (creates the entry if needed) |
| Main (trusted) | `forget_window` | removes the entry |

At most 16 windows are kept (oldest dropped); a tab list holds at most 100 tabs; `layout` at most
64 KiB serialized (`invalid_args`).

### 2.3 `.unfold/local/state.json` (per project) — changed

```jsonc
{
  "version": 1,
  "backgroundUpdates": true,
  "emptyFolders": ["Checkout/Refunds"],           // folders with no board in them (R-10), sorted
  "boards": {                                     // view state per BoardId (R-9)
    ".unfold/boards/order-lifecycle.json": {
      "page": "page-2",                           // last active page, or null
      "pages": { "page-1": { "x": -120, "y": 40, "zoom": 0.85, "lens": "flow" } }   // lens: "code"|"flow"|null
    }
  }
}
```

- **Leaves it:** `windows` (to `windows.json`).
- Before the first Compile, nothing may be written in the folder: changes are kept in memory and
  written when `local/` is created (V1 rule). Empty folders and view state need drafts or published
  boards, so in practice they arrive after the first Compile.
- Rust keeps it consistent: a published or unpublished board's view entry moves with its id;
  `delete_board` removes it; `emptyFolders` loses a folder once a board goes into it or under it.
- At most 500 board entries (least recently written dropped) and 200 pages per board.

### 2.4 `.unfold/config.toml` — one new table

```toml
[project]
name = "storefront-api"     # optional; the shared name other projects' boards use
```

Strict like every table (unknown keys refused). `Settings::project_name: Option<String>`, **excluded**
from `Settings::hash()` and `python_hash()` (a rename re-extracts nothing). Edited through
`update_project_config` with `{kind: "set_project_name", name: string | null}` (null removes the
table); written only when it differs from the current text (V1 rule).

### 2.5 Deleted

- `recent.json`: its folder list and welcome bounds have no role (recent **boards** live in
  `workspace.json`; there is no welcome window). Delete the file's code; the app ignores a stale file.
- `FolderState.windows` and `WindowState` (V1 shape).

## 3. Host lifecycle

### 3.1 The addon surface (`unfold-node`) and `Host`

| Addon export | `Host` | Notes |
| --- | --- | --- |
| `init(options: string): void` | `init(&str)` | Unchanged: `{"appDataDir","logsDir","fallbackCacheDir"}`. Loads `workspace.json`; every project starts **resting** |
| `subscribe(sink): void` | `subscribe` | Unchanged |
| `dispatch(windowId, requestId, command): Promise<string>` | `dispatch_async` | Unchanged. Any window id is accepted; the window needs no attach |
| `cancel(requestId): void` | `cancel` | Unchanged |
| `detachWindow(windowId): Promise<void>` | `detach_window_async` | **New.** Waits (≤ 15 s, `CLOSE_WAIT`) for the window's closing writes in flight, then releases its board claims and sessions and its Home selection. Projects losing interest start their grace lease |
| `shutdown(): Promise<void>` | `shutdown_async` | **New.** Closes every live project (writing `lastKnown` to `workspace.json`); called once when the app quits |

Deleted: `openWorkspace`, `closeWorkspace` (and `Host::open_workspace*`, `Host::close_workspace*`,
`OpenedFolder`, `Registry::open/close/workspace(window)`). Windows are no longer attached to anything
in Rust: a window is known by the id its commands carry.

`CLOSING_WRITES` (Rust `host.rs` and `router.ts`, kept in sync): `save_board`, `repair_board`,
`publish_board`, `discard_changes`, `unpublish_board`, `delete_board`, `duplicate_board`,
`set_board_folder`, `create_folder`, `rename_folder`, `delete_folder`, `save_board_view`,
`save_window_state`, `save_window_bounds`.

### 3.2 The projects registry (Rust)

`crates/unfold-workspace/src/projects.rs` replaces `registry.rs`:

```text
Projects (one per Host)
  workspace file   (workspace.json, cached in memory, written on change)
  windows file     (windows.json)
  entries: ProjectId -> ProjectEntry {
      row:       path, name, expanded, repository, lastKnown
      live:      Option<Arc<Workspace>>          // open engine, watcher, store writer, lock
      resting:   Option<RestingReader>           // lazily opened read-only pool (see 3.4)
      extras:    ProjectExtras                   // V1 FolderExtras: file set, render cache, board
                                                 // sessions, health cache; dropped on rest/switch
      claims:    BoardClaims                     // BoardId -> WindowId (V1 type, per project)
      interest:  selected_by: Set<WindowId>, compile_pins: u32, lease_until: Instant
  }
  selection: WindowId -> ProjectId
```

`Ctx` gives handlers: `ctx.project(id) -> CommandResult<ProjectHandle>` (no wake; `unknown_project`
for an unknown id) and `ctx.live(id) -> CommandResult<Arc<Workspace>>` (wakes it and extends its
lease, [§3.3](#33-live-and-resting-projects)). `ctx.workspace()` is deleted.

### 3.3 Live and resting projects (R-8)

Rust owns liveness (D-8); the router knows nothing about projects.

```text
interest(p) =  any window holds a claim on a board of p
            || any window has p selected (select_project)
            || an open board session (in any project) has cards resolving to p     // cross-project pages
            || a compile/rebuild request of p is running (compile pin)

wake(p):  on a command marked "wakes" in §4, on open_board/new_board, on select_project(p),
          on gaining interest. Opens Workspace (V1 open: readable at once; the reopen job checks
          files by size and mtime in the background), installs the watcher, emits project_state.
          A wake that fails (open_elsewhere, not_a_folder) sets state unavailable{reason} and the
          command fails with that error.
lease:    every waking command and every loss of interest sets lease_until = max(lease_until, now + rest_after)
rest(p):  when live && !interest && now >= lease_until && the engine is idle (nothing running,
          queued, or due). Writes lastKnown to workspace.json, closes the Workspace (stops watcher and
          engine thread, releases the lock, drops the ReaderIndex), drops extras, emits project_state.
reaper:   one thread ("unfold-liveness") checks every reap_interval; it also closes resting read pools
          unused for 60 s.
```

`WorkspaceOptions` gains `rest_after` (default 300 s) and `reap_interval` (default 30 s); tests
shorten them. `select_project` wakes synchronously (it returns after the open), so the UI's next
Home query finds the project live. A project selected in no window, with no tab and no lease, rests
five minutes after its last use.

### 3.4 How a resting project answers reads

A resting project holds no watcher, engine thread, lock, in-memory program, or `ReaderIndex`. The
commands marked **rests** in §4 serve it from disk:

- **The stored graph**: a `RestingReader` opens `graph.sqlite` read-only through the new
  `unfold_store::ReadPool::open_existing(path, engine_version) -> Result<Option<ReadPool>>` (one idle
  reader, checks `schema_version` and `engine_version` read-only; `None` when the file is missing or
  stale, which reads as "no graph"). The path comes from `Layout::discover` (no writes; fallback
  location honored).
- **Files** (file search, text search): the stored graph's `files` table (indexed sources only),
  not a discovery walk (D-9). A resting project that was never compiled has no files to search.
- **Boards** (`list_boards`, `drafts`, `board_refs`, `board_thumbnails`): read from disk;
  `emptyFolders` from `state.json` read in place. Health labels are `null` for a resting project
  (health needs a current graph).
- **State**: `lastKnown` from `workspace.json`.

A result from a resting project **wakes it when it is used**: every command that takes a key or path
of the project (preview, card, peek, file_view, relations, open_board, …) is marked **wakes** (D-10).

### 3.5 Board claims

A board is open in one window at a time (U-37). Claims are per `(project, BoardId)`: `open_board`
and `new_board` claim it for the calling window, `move_board` transfers it, `close_board` and
`delete_board` release it, `detachWindow` releases all of a window's claims. Every other board command
checks the calling window holds the board (`board_held` / `board_not_held`, unchanged). Folder
operations and `set_board_folder` are the exceptions: the folder is Rust-owned metadata, never part of
what the UI saves ([§6.5](#65-what-the-ui-sends-boardedit)), so they work on any board, held or not.

### 3.6 Shutdown and engine restarts

- **Quit:** the main process sends `shutdown` to the engine host; the router detaches every window
  (closing writes land first), then calls `binding.shutdown()`; then the process exits.
- **Engine host restart:** Rust starts with every project resting. On reconnect, each window's UI must
  (in this order) call `select_project` with its selection, `open_board` for each board tab (re-claim),
  then save any unsaved edits (`save_board`; a `board_conflict` follows the V1 rule), and drop cached
  queries (the V1 refetch-after-restart rule).

## 4. Commands

Conventions are V1's: `{"command", "args"}`, camelCase, `deny_unknown_fields`, optional fields are
`#[serde(default)]` + `#[ts(optional)]`, results serialize camelCase, errors are `{code, message}`.
**Every command that concerns one project takes `project: ProjectId` as its first argument.** Paths a
window names are relative to that project's current folder and confined there.

Columns: **T** = trusted only (main process); **L** = liveness: `wakes` (opens the project and extends
its lease), `rests` (served from disk when resting, [§3.4](#34-how-a-resting-project-answers-reads)),
or `—` (no project).

### 4.1 Shared types

```ts
type ProjectId = string;        // "p-" + 10 × [a-z2-7]
type ProjectName = string;      // /^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/
type BoardId = string;          // ".unfold/boards/<name>.json" | ".unfold/local/drafts/<name>.json"
type PageId = string;
type Key = string;              // structural block or entrance key (V1)
type WindowId = number;
type Ms = number;               // ms since the Unix epoch
type View = "code" | "flow";

type ProjectState =             // §4.10 of the redesign; one indicator per row
  | { kind: "current" }
  | { kind: "compiling"; done: number; total: number }      // a Compile or Rebuild
  | { kind: "updating"; files: number | null }               // a background update
  | { kind: "problems"; count: number }                      // count = problems(project).length
  | { kind: "paused"; changed: number }
  | { kind: "not_compiled" }
  | { kind: "failed"; message: string }
  | { kind: "resting"; last: ProjectState; atMs: Ms }        // last ∈ current|problems|paused|not_compiled|failed
  | { kind: "unavailable"; reason: string };                 // the folder is gone, or open elsewhere
// Derived for a live project from GraphStatus and the Problems count, first match wins:
// failed > compiling > updating > paused > not_compiled > problems (count > 0) > current.
// A resting project that has never been live has last = not_compiled when it has no .unfold/local/cache,
// else current.

interface ProjectRow {
  id: ProjectId; name: ProjectName; path: string; expanded: boolean; live: boolean;
  state: ProjectState;
  git: { branch: string | null; detached: string | null; worktrees: number } | null;  // null: no repository
}
interface WorkspaceView { projects: ProjectRow[]; selected: ProjectId | null; recentBoards: RecentBoard[];
  removed: RemovedProject[] }                                               // A-1: "Opened before", most recent first
interface RemovedProject { path: string; name: ProjectName; removedAtMs: Ms }
interface RecentBoard { project: ProjectId; board: BoardId; title: string; openedAtMs: Ms }

interface GitInfo {
  branch: string | null; detached: string | null;
  worktrees: { root: string; path: string; branch: string | null; detached: string | null;
               main: boolean; current: boolean; available: boolean }[];   // path = root/subpath
}
```

### 4.2 Workspace

| Command | Args | Result | T | L | Notes |
| --- | --- | --- | --- | --- | --- |
| `workspace` | `{}` | `WorkspaceView` | | — | Reads HEAD of every repository (cheap). ≤ 64 projects, ≤ 20 recents |
| `add_project` | `{path: string}` (absolute, from a dialog, a drop, or argv) | `{status: "added" \| "exists"; project: ProjectRow}` | ✓ | — | Canonicalizes; `exists` for the same folder or the same repository identity. Writes nothing in the folder. New row appended, expanded, resting. `not_a_folder`, `too_many_projects` |
| `remove_project` | `{project}` | `null` | | — | `boards_open` if any window holds one of its boards. Closes it if live, drops its recents, never touches `.unfold/`. Emits `project_reset`, `workspace_changed` |
| `reorder_projects` | `{order: ProjectId[]}` | `WorkspaceView` | | — | Must be a permutation of the ids (`invalid_args`) |
| `set_project_expanded` | `{project, expanded: boolean}` | `null` | | — | Emits `workspace_changed` |
| `select_project` | `{project: ProjectId \| null}` | `null` | | wakes | The calling window's Home selection: interest for liveness; also `workspace.json` `selected`. No event |
| `git_info` | `{project}` | `GitInfo \| null` | | rests | ≤ 64 worktrees |
| `switch_worktree` | `{project, path: string}` | `ProjectRow` | | — | `path` must equal an `available` worktree `path` from `git_info` (`not_a_worktree`); `boards_open`. See §1.2 |
| `drafts` | `{}` | `{drafts: BoardSummary[]}` | | rests | One fan-out over every project: drafts, and published boards with `changes > 0`; by `updatedAtMs` desc; ≤ 500 |

There is no `rename_project`: a project has one name, the shared name, changed with
`update_project_config` `set_project_name` (D-11).

### 4.3 Project, Home, settings

| Command | Args | Result | T | L | Notes |
| --- | --- | --- | --- | --- | --- |
| `project_summary` | `{project}` | `ProjectSummary` | | wakes | Home's header and Health line |
| `compile_preview` | `{project}` | `CompilePreview` | | wakes | V1 `folder_summary` minus `folder`/`name`/`compiled`/`status`; walks the folder, writes nothing |
| `scope_dir` | `{project, path: string}` (`""` = root) | `{path; folders: ScopeFolder[]; truncated: boolean}` | | wakes | The scope tree: one level, **folders only**, ≤ 2,000, sorted by name |

## 5. Events

Every project event carries `project: ProjectId` (replacing `folder`) and is sent to **every window**
(`{"kind":"broadcast","event":…}`); only `board_conflict` is targeted (`{"kind":"event","windows":[w]}`).
Rust no longer lists windows for project events. `SinkMessage` keeps its three kinds.

| Event | To | When | Payload |
| --- | --- | --- | --- |
| `workspace_changed` | all | A row was added, removed, reordered, expanded or collapsed, renamed (shared name), switched; recents changed | `{workspace: WorkspaceView}`: the UI replaces its `workspace` query data (no refetch) |
| `project_state` | all | A row's `ProjectState` changed (including live ↔ resting); not on every progress tick | `{project, state: ProjectState}` |
| `project_reset` | all | The project's folder changed (worktree switch) or it was removed: everything cached for it is stale | `{project}` |
| `compile_progress` | all | Throttled, as V1 | `{project, stage, done, total}` |
| `graph_updated` | all | A commit changed the graph | V1 fields with `project` |
| `problems_changed` | all | The Problems list changed | `{project, count}` |
| `files_changed` | all | The watcher saw files change | `{project, paths, truncated}` |
| `boards_changed` | all | Board files, folders, or a board's publish state changed (outside the app or by a command) | `{project, boards: BoardId[], folders: boolean}` (a copy's change is reported under its published id) |
| `board_conflict` | the holder | The file the board's session reads changed on disk outside the app | `{project, board: BoardId, file: "draft" \| "changes" \| "published", savedRevision, diskRevision: string \| null}` |
| `config_changed` | all | `.unfold/config.toml` changed | `{project}` |
| `preferences_changed` | all | Unchanged | `{preferences}` |

Deleted: `folder_opened`, `graph_status`.

**UI invalidation** (keys are `["engine", command, args]`; every project command's args hold
`project`, so predicates test `args.project === event.project`): `graph_updated` → V1 rules restricted
to the project, plus `entrances` (entrances or inputs changed), `project_summary`, `preview`,
`callers`, `board_thumbnails`, and `board_health` of every open board whose document has cards
resolving to that project; `search`/`search_text` results that included it. `files_changed` → V1
rules restricted to the project. `boards_changed` → that project's `list_boards`, `board_thumbnails`
of the listed ids, `drafts`, `board_refs`, `project_summary`. `problems_changed` → `problems`,
`project_summary`. `config_changed` → `project_config`, `compile_preview`, `scope_dir`. `project_state`
→ write into the `workspace` row; invalidate `project_summary`. `project_reset` → remove every query
whose `args.project` is the project. `workspace_changed` → set `workspace`.

## 6. The board format

### 6.1 Files

| What | Path | Holds |
| --- | --- | --- |
| Draft | `.unfold/local/drafts/<name>.json` | A board document |
| Published | `.unfold/boards/<name>.json` | A board document (never `publishes`/`baseRevision`) |
| Unpublished changes of a published board | `.unfold/local/drafts/<name>.changes.json` | A board document + `publishes: "boards/<name>.json"` + `baseRevision` (D-6) |

### 6.2 The JSON shape (`unfold-board`, `version` 1)

```jsonc
{
  "format": "unfold-board",
  "version": 1,
  "title": "Order lifecycle",
  "folder": "Checkout",                       // optional; absent = top level
  "projects": ["storefront-web"],             // other projects' shared names its cards use; sorted, unique; always written
  "pages": [                                  // ≥ 1; order is the board's page order
    {
      "id": "page-1",
      "title": "Placing an order",
      "defaultView": "flow",
      "cards": [
        { "id": "checkout", "at": [0, 0],
          "ref": { "entrance": "entrance:[\"next.route\",\"http\",\"POST\",\"/api/cart/checkout\"]", "project": "storefront-web" } },
        { "id": "post-orders", "at": [320, 0],
          "ref": { "entrance": "entrance:[\"express.route\",\"http\",\"POST\",\"/orders\",\"requireUser\"]" } },
        { "id": "create-order", "at": [640, 0], "view": "flow", "folded": true,
          "ref": { "block": "src/routes/orders.ts#function:createOrder" },
          "description": { "author": "person:you", "signature": "sha256:…", "text": "Places the order now, or queues it." } }
      ],
      "groups": [
        { "id": "queue-or-place", "card": "create-order", "title": "Queue or place now", "collapsed": false,
          "members": ["src/routes/orders.ts#function:createOrder/if[0]"] }
      ],
      "labels": [                             // Flow-node labels; sorted by (project ?? "", key); unique per (project, key)
        { "key": "src/routes/orders.ts#function:createOrder/if[0]", "author": "person:you",
          "signature": "sha256:…", "text": "Did the client ask for an async reply?" }
      ],
      "guards": [                             // one per referenced (project, key); sorted like labels
        { "key": "src/routes/orders.ts#function:createOrder", "kind": "function",
          "owner": "src/routes/orders.ts#function:createOrder", "signature": "sha256:…" },
        { "key": "entrance:[\"next.route\",…]", "project": "storefront-web", "kind": "entrance:http",
          "owner": "", "signature": "sha256:…" }
      ],
      "links": [                              // drawn links (R-7); sorted by id
        { "id": "checkout-calls-orders", "from": "checkout", "to": "post-orders",
          "label": { "author": "person:you", "signature": "sha256:…", "text": "calls over HTTP" } }
      ]
    }
  ]
}
```

| Field | Rule |
| --- | --- |
| `format`, `version` | `"unfold-board"` and `1`. Anything else is refused |
| `title` | Not blank |
| `folder` | Optional; a folder path (§1.4); `""` refused |
| `projects` | Exactly the sorted set of `ref.project` values used by any card of any page (refused otherwise); `[]` allowed |
| `pages` | ≥ 1; ids unique (§1.4) |
| page `title` | Not blank |
| page `defaultView` | `"code"` or `"flow"` |
| `cards[]` | V1 card; `ref` is exactly one of `block` / `entrance` plus optional `project` (a `ProjectName`) |
| `groups[]` | V1 group; `card` names a block card **of this page**; members are keys of that card's project |
| `labels[]` | `{key (a block key), project?, text, author, signature}`; `signature` may be `""` on input (signed on save) |
| `guards[]` | `{key, project?, kind, owner, signature}`; optional on input, always written |
| `links[]` | `{id, from, to, label?}`; `from` ≠ `to`, both card ids of this page; `label` is a description |
| `publishes`, `baseRevision` | Only in a `*.changes.json` draft: `"boards/<name>.json"` matching its file name, and 64 lowercase hex digits. Refused anywhere else |

V1's rules carry over unchanged: strict parsing with JSON pointers in errors (unknown fields,
duplicate keys, wrong types refused), descriptions and labels (`text` not blank, `author`
`person:`/`agent:`, `signature` `sha256:<64 hex>` or `""`), group rules, guard kinds, 16 MiB file cap.
A ref without `project` is the board's own project; a save that names the board's own project's
current shared name in `ref.project` is refused (`invalid_args`, "omit project for the board's own
project").

**Deterministic writer** (V1 rules): object keys sorted by UTF-16 code units, numbers and escapes as
`JSON.stringify(v, null, 2)`, two-space indent, final newline. Arrays: `pages` in document order;
`cards`, `groups`, `links` by id; `labels`, `guards` by (`project` ?? `""`, `key`); `projects`
sorted. `folded` written only when true; optional fields omitted when absent. Load-then-save
reproduces a file byte for byte.

`docs/schemas/unfold-board.schema.json` and its source `crates/unfold-reader/schema/` are rewritten to
this shape (`$id` `…/unfold-board-1.schema.json`); `tools/oracles/check-board-schema.mjs` still checks
the two copies are identical and validates the sample board.

### 6.3 Signatures, guards, links

- Card, group, and label signatures are V1's, computed against the graph of the ref's project.
- A **link label** is signed with `sha256:` of `"<from card signature>\n<to card signature>"` (each
  the end's current guard signature in hex) when saved. It is informational: health never marks a
  link outdated (R-7).
- Guards are recorded per (project, key) for every referenced key of a connected project; guards of
  a not-connected project are kept as they are (never dropped, never checked).

### 6.4 Health (per page, per project)

`BoardHealth` = V1 `Health` with every `HealthItem` gaining `page: PageId` and an optional
`project: ProjectName` (for labels and keys), plus two counters and kinds:

| Kind | When | Target | Repairs |
| --- | --- | --- | --- |
| `missing`, `outdated`, `brokenGroup`, `review` | V1 rules, against the graph of the card's project | V1 | V1 |
| `notConnected` | A card's `ref.project` resolves to no connected project (placeholder: "From <name>, not connected") | `card` | `removeCard` |
| `brokenLink` | A link end's card is `missing` (its key is gone from its connected project) | `link` | `removeLink` |

Labels, groups, and guards of a not-connected project are not checked. `label` (the list label)
gains "N not connected" and "N broken links". A not-connected card is never a save error (V1's "no
**new** missing references" rule applies only to connected projects).

**Resolving projects for a page:** `PageGraphs = Map<ProjectName | own, BoardGraph>`; each connected
project's `BoardGraph` is loaded from that project's reader (live pool or resting read pool) for the
keys the page references in it. Loading another project's graph never wakes it.

### 6.5 What the UI sends (`BoardEdit`)

```ts
interface BoardEdit { title: string; pages: PageDoc[] }   // PageDoc = §6.2 page; labels/guards/links optional on input
```

`folder`, `projects`, `format`, `version`, `publishes`, and `baseRevision` are not part of an edit:
Rust takes `folder` from the session, derives `projects`, and owns the file framing. So folder
operations never race the UI's autosave (D-12). `save_board` then runs V1's `prepare_save` per page
and per connected project (restores dropped guards, signs unsigned text, refuses new missing
references, broken groups, or held references), signs link labels, and writes.

Pages whose content equals the session's are not re-checked (their health is reused).

### 6.6 Unpublished changes (R-6)

The session of a board knows its **working file**: the draft file; or, for a published board, the
`*.changes.json` copy when one exists, else the published file.

| Action | Draft | Published, no copy | Published, with copy |
| --- | --- | --- | --- |
| `save_board` | Writes the draft (V1) | Writes a new copy with `baseRevision` = the published revision the session loaded; session now on the copy | Writes the copy |
| `save_board` making the working version equal to the published one (`changes` = 0) | — | — | Deletes the copy; session back on the published file |
| `publish_board` | Creates `boards/<name>.json`, never overwriting (`name_taken`); deletes the draft; new id | No-op (`done`) | Published revision == `baseRevision` → copy written over the published file atomically, copy deleted. Otherwise `conflict` unless `resolve: "keep_mine"` (then written anyway). A deleted published file is a conflict with `theirsRevision: null`; keep mine recreates it |
| `discard_changes` | `invalid_args` | No-op | Deletes the copy; reloads the published file |
| `unpublish_board` | `invalid_args` | Published content becomes a draft | The copy's content becomes a draft; copy and published file deleted |
| `delete_board` | Deletes the draft | Deletes the published file | Deletes both |

- **`changes`** counts differences between the working and the published version: `title` (1),
  `folder` (1), page order (1), each page added or removed (1), and for each page present in both:
  `title`/`defaultView` (1), plus each card, group, and link added, removed, or changed (by id), and
  each label added, removed, or changed (by project and key). Guards are not counted.
- **`baseChanged`** = the published file's revision ≠ the copy's `baseRevision` (a pull changed it).
- **`board_conflict`** is about the working file: for a published board without a copy, its published
  file; with a copy, the copy. The V1 UI rule holds: no unsaved edits → `reload_board`; unsaved edits
  → ask; keep mine = `save_board {force: true}` (for a published board without a copy, the new copy's
  base is then the published revision now on disk), take theirs = `reload_board`.
- The watcher reports a change to `x.changes.json` as `boards_changed` for `.unfold/boards/x.json`.

### 7.1 Transport (`desktop/src/shared/transport.ts`)

type HostToMain = { type: "result"; id: number; ok: true; value: unknown }

### 7.2 Router (`desktop/src/engine-host/router.ts`)

- `attach(windowId, port)`: no folder, no `openWorkspace`, no `workspaceReady`: commands dispatch at
  once. A re-attach of the same id (reload) swaps the port; Rust state for the window (claims,
  selection) is untouched.
- `detach(windowId)`: as V1 `release`: cancel the window's non-closing requests, wait for its closing
  writes (its own and the main process's trusted ones) to reach `dispatch`, then
  `binding.detachWindow(windowId)` (serialized per window).
- `shutdown()`: detach every window, await those detaches, then `binding.shutdown()`.
- Sink: `event` → the listed windows; `broadcast` → every connected port; `stream` → by request id
  (unchanged). No project knowledge in the router.
- `MAIN_PROCESS_ONLY = {export_mermaid, add_project, saved_windows, save_window_bounds, forget_window}`;
  `CLOSING_WRITES` as in [§3.1](#31-the-addon-surface-unfold-node-and-host). The `RouterEvents.attached`
  hook and `postIfCurrent` for `workspace_open_failed` are deleted.
- `binding.ts`: `EngineBinding = {init, subscribe, dispatch, cancel, detachWindow, shutdown}`.

## 10. Decisions made here

| ID | Decision | Why |
| --- | --- | --- |
| D-1 | Project ids are random (`p-` + 10 base32 chars), not paths | A worktree switch changes the path; tabs and recents must survive it |
| D-2 | Default shared name = the main worktree's folder name for a repository root (else the folder's), slugged if invalid | All worktrees of one repository share a name, so cross-project refs survive switching |
| D-3 | A shared name resolves to the first connected project in workspace order | One deterministic rule for Rust and the UI; duplicates are rare (two clones) |
| D-4 | HEAD is read on every `workspace`/`git_info` call; no `.git` watching | Cheap file reads; the watcher already drops `.git/`; the UI refetches on focus |
| D-5 | A published board's id stays the published path while it has unpublished changes | Tabs, claims, and recents must not change identity on the first edit |
| D-6 | The changes copy is `drafts/<name>.changes.json`; drafts never end in `.changes` | Deterministic lookup without scanning drafts; satisfies R-6's `drafts/<id>.json` with `publishes` |
| D-7 | A published file's name is fixed at first Publish; Rename changes the title only | A file rename is a shared Git change that R-6 can't hold as an unpublished change |
| D-8 | Rust owns liveness (claims, `select_project`, leases); the router stays project-blind | Rust already sees claims and commands; one owner, testable in Rust |
| D-9 | Resting projects search files from the stored graph's `files` table | No disk walk without a watcher to invalidate it; R-8 says "from their stored graph" |
| D-10 | Using a result (any key- or path-taking command) wakes its project; listing it does not | Implements "a result from a resting project wakes it" with one rule |
| D-11 | One project name (the shared name); no workspace-only display name or `rename_project` | Two names for one row would confuse cross-project boards |
| D-12 | `folder` is Rust-owned metadata: not in `BoardEdit`; folder commands work on held boards | No race between folder operations and autosave; no `board_held` dead ends |
| D-13 | Card, label, guard, and link data stay per page; links live in the page, not the board | Links join cards, and cards belong to a page |
| D-14 | Labels and guards are arrays of `{project?, key, …}` instead of maps | Keys can repeat across projects; arrays keep the strict, sortable, unambiguous shape |
| D-15 | `projects` must equal the set of `ref.project` values (strict) | One supported shape; agents and teammates get an error instead of a silently wrong list |
| D-16 | The format keeps `version: 1` | Nothing shipped; there is one version and no history to number |
| D-17 | No board-level description | Not in R-5 or the designs |
| D-18 | Link labels are signed over both ends' signatures but never reported outdated | R-7: health checks only that both ends exist |
| D-19 | Every project event is broadcast to all windows; only `board_conflict` is targeted | R-2: every window shows the workspace; events are small and throttled |
| D-20 | `select_project` wakes synchronously; resting starts after `rest_after` (300 s) with the engine idle | Home's queries find the project live; a project never rests mid-update |
| D-21 | `remove_project` and `switch_worktree` refuse with `boards_open` | Never lose unsaved edits held in another window |
| D-22 | `entrances` is per project, paged per application (default 8), filtered in Rust | Home and Add share it; invalidation by `graph_updated` per project; small payloads |
| D-23 | Board health is computed for all boards of a project (cached), feeding Problems and Home | Home's Health line lists boards that need review, not only open ones |
| D-24 | `changes` = a structural diff count; a copy equal to the published version is deleted | "N unpublished changes" is meaningful and never "0 unpublished changes" |
| D-25 | Per-window Home selection in `windows.json`; `workspace.json` `selected` is the default for new windows | Two windows can show different projects on Home |
| D-26 | Thumbnails give card positions, kinds, views, folds, and line counts; TS computes rectangles | Rust doesn't know measured sizes (Rust computes, TS lays out) |
| D-27 | Engine-host restart: the UI re-selects, re-opens its board tabs, then saves | Claims and selections live only in Rust memory |
